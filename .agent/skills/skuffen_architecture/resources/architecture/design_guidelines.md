# Design Guidelines

## General Information

Skuffen is a **middleware archiving service** designed to provide a stable, asynchronous interface on top of the Sikri Archive API. Skuffen shall be built such that it can continue to function even if the Sikri Archive API is unavailable.

## Philosophy

### Stability & "Best Effort"
Skuffen uses an internal operation queue to ensure "Best Effort" availability. This allows the system to accept requests even when the underlying archive system is down, processing them once connectivity is restored.
Best effort refers to the design choice that if an operation in the context of a case fails, the next legal operation will be executed. This means that a failure will not cause the whole queue to be blocked.

### Async First
The system favors asynchronous operations to decouple the ingestion of requests from the processing speed and availability of external systems.

Specific choices in this regard:
*   The system uses NATS for communication between components.
*   The system uses a message queue to decouple the ingestion of requests from the processing speed and availability of external systems.
*   The system takes in commands with request-reply, validates the command, and puts it in an internal queue.
*   All commands to external systems have their execution state stored for retriability and reporting to the client system.
*   The system uses a NATS stream to report the execution state of commands to external systems.

### Idempotency

Each command has a command Id, which is used to ensure idempotency. The command Id is a UUID.

### Client Reference

As the backend archive system may be unavailable, the contract specifies a client reference for each entity. This is a UUID that is generated by the client system and is used to identify the entity in question. This means that a client can send in a command such as "Opprett sak" with a client reference <client_reference>, and later send in a command such as "Opprett journalpost" on sak <client_reference>, and the system will know that the client is referring to the same sak.
